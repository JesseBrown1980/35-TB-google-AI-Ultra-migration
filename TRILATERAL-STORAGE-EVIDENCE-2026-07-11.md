## Current reality

The local HDD/USB storage substrate and pluggable store interface are the proven base. This repository
is the Google Drive adapter plan/scaffold and remains gated on local operator authentication plus a
successful write/read/SHA round trip.

Trilateral evidence does not turn the planned cloud leg into a live one. It strengthens the route to
measurement:

```text
origin seat -> adapter implementation and local auth-gated run
attack-verify seat -> independent source/config review
third seat -> credential-free tests, interface/parity checks, or own-account run
CI -> committed-head tests without private credentials
```

## Storage is real system work

HDD/SSD/USB/cloud can hold cube bodies, retained Path-1 content, Path-2 shadows, receipts, queues,
archives, and cold state. That makes storage-rich machines real Asolaria participants. It does not
mean storage performs GNN or LLM tensor arithmetic.

## Claim tags

- local store behavior: `MEASURED_REPO` or seat-specific measurement;
- GoogleDriveStore source before authenticated round trip: implementation/scaffold;
- authenticated write/read/hash match: `MEASURED_<SEAT>` with receipt;
- 35 TB account capacity: operator/account entitlement, not bytes already occupied;
- cross-seat cloud availability: separate per account/key/vantage;
- missing credentials: gated boundary, not broken code.

## Security and authority

Third-seat or CI verification must not receive operator credentials. Private keys and ADC material
stay local. No merge may include tokens, account identifiers, private bodies, or automatic cloud
writes.

## Merge rule

Merge interface code, mocks, credential-free tests, docs, and secret-clean adapters when checks pass.
Hold authenticated writes, migrations, retention-policy changes, and cutover until the operator-run
round trip emits its scoped receipt.
